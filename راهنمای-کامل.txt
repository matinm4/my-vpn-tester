═══════════════════════════════════════════════════════════════════════
  بخش ۰ — این پروژه چه کار می‌کند؟
═══════════════════════════════════════════════════════════════════════

این پروژه کانفیگ‌های وی‌پی‌ان (vmess، vless، trojan، shadowsocks) را از
لینک‌های ساب و کانال‌های تلگرام جمع می‌کند، بعد **هر کدام را واقعاً تست
می‌کند** و بهترین‌ها را به شما می‌دهد.

«واقعاً تست می‌کند» یعنی چه؟

  اکثر تسترها فقط چک می‌کنند که سرور روشن است یا نه. این کافی نیست —
  سروری که روشن است ممکن است رمزش عوض شده باشد و اصلاً کار نکند.

  این پروژه برای هر کانفیگ یک تونل واقعی باز می‌کند، از داخل آن تونل به
  اینترنت وصل می‌شود، و می‌بیند واقعاً جواب می‌دهد یا نه.

  به همین دلیل نتیجه‌اش قابل اعتماد است. و به همین دلیل معمولاً فقط
  ۲ تا ۵ درصد کانفیگ‌ها سالم در می‌آیند — بقیه واقعاً مرده‌اند.

روی گیت‌هاب چه اتفاقی می‌افتد؟

  • هر ۳۰ دقیقه: ۲۰ کانفیگ برتر دوباره تست می‌شوند. هر کدام که از کار
    افتاده باشد، فوراً با بهترین جایگزین بعدی عوض می‌شود.

  • هر ۶ ساعت: یک دور کامل — کانفیگ‌های جدید جمع و تست می‌شوند.

  همه‌ی این‌ها روی سرورهای گیت‌هاب انجام می‌شود، **رایگان**، بدون اینکه
  کامپیوتر شما روشن باشد.


═══════════════════════════════════════════════════════════════════════
  بخش ۱ — ساخت حساب گیت‌هاب
═══════════════════════════════════════════════════════════════════════

اگر از قبل حساب گیت‌هاب دارید، این بخش را رد کنید.

۱. به این آدرس بروید:

      https://github.com/signup

۲. ایمیل، رمز و یک نام کاربری وارد کنید.

   ⚠ نام کاربری را یادداشت کنید — بعداً لازمش دارید.
     در این راهنما هر جا نوشته USERNAME، یعنی همین.

۳. ایمیل‌تان را تأیید کنید (گیت‌هاب یک کد می‌فرستد).

   نکته: اگر سایت گیت‌هاب باز نمی‌شود، فیلترشکن‌تان را روشن کنید.


═══════════════════════════════════════════════════════════════════════
  بخش ۲ — نصب گیت روی کامپیوتر
═══════════════════════════════════════════════════════════════════════

گیت ابزاری است که فایل‌ها را به گیت‌هاب می‌فرستد.

۱. بررسی کنید شاید از قبل نصب باشد:

   • کلید Windows را بزنید
   • تایپ کنید:  cmd
   • Enter بزنید (پنجره‌ی مشکی باز می‌شود)
   • این را تایپ کنید و Enter بزنید:

         git --version

   اگر چیزی شبیه «git version 2.51.0» دید، نصب است — به بخش ۳ بروید.
   اگر خطا داد، ادامه دهید.

۲. دانلود از:

      https://git-scm.com/download/win

۳. فایل دانلودشده را اجرا کنید. در تمام مراحل فقط Next را بزنید.
   هیچ تنظیمی را عوض نکنید.

۴. بعد از نصب، **پنجره‌ی cmd را ببندید و دوباره باز کنید**، بعد دوباره
   امتحان کنید:

         git --version


═══════════════════════════════════════════════════════════════════════
  بخش ۳ — ساخت مخزن (repository)
═══════════════════════════════════════════════════════════════════════

مخزن یعنی جایی که فایل‌های پروژه روی گیت‌هاب نگه داشته می‌شوند.

۱. به این آدرس بروید:

      https://github.com/new

۲. این‌ها را پر کنید:

   • Repository name  →  یک اسم دلخواه، مثلاً:  my-vpn-tester
                          (فقط حروف انگلیسی و خط تیره)

   • Description      →  خالی بگذارید

   • Public / Private →  ⚠ حتماً  Public  را انتخاب کنید

     چرا Public؟
       چون گیت‌هاب برای مخزن عمومی اجرای نامحدود و رایگان می‌دهد.
       برای مخزن خصوصی فقط ۲۰۰۰ دقیقه در ماه می‌دهد که کم است.

     حافظه‌ی پروژه رمزنگاری‌شده است، ولی فایل‌های خروجی برای هر کاربر
     لاگین‌شده‌ی گیت‌هاب که آدرس مخزن را بداند قابل دانلودند.
     اگر این را نمی‌خواهید، Private را انتخاب کنید و زمان‌بندی را کم
     کنید. توضیح کامل هر دو حالت در بخش ۱۲.

   • تیک‌های  Add a README / .gitignore / license  →  همه را خالی بگذارید

۳. دکمه‌ی سبز  Create repository  را بزنید.

۴. صفحه‌ای باز می‌شود با یک آدرس شبیه این:

      https://github.com/USERNAME/my-vpn-tester.git

   ⚠ این آدرس را یادداشت کنید. در بخش بعد لازمش دارید.


═══════════════════════════════════════════════════════════════════════
  بخش ۴ — آپلود پروژه
═══════════════════════════════════════════════════════════════════════

۱. پوشه‌ی پروژه را در File Explorer باز کنید:

      E:\ai_coding\vtester-actions

۲. در نوار آدرس بالای پنجره کلیک کنید (جایی که مسیر نوشته شده)،
   همه‌اش را پاک کنید، تایپ کنید  cmd  و Enter بزنید.

   یک پنجره‌ی مشکی باز می‌شود که از قبل داخل همین پوشه است.

۳. این دستورها را **یکی یکی** کپی کنید، بعد از هرکدام Enter بزنید:

      git remote add origin https://github.com/USERNAME/my-vpn-tester.git

   ⚠ به‌جای USERNAME و my-vpn-tester آدرس خودتان از بخش ۳ را بگذارید.

      git push -u origin main

۴. یک پنجره باز می‌شود و از شما می‌خواهد وارد گیت‌هاب شوید:

   • روی  Sign in with your browser  بزنید
   • در مرورگر  Authorize  را بزنید
   • به پنجره‌ی cmd برگردید

۵. اگر موفق بود، چیزی شبیه این می‌بینید:

      branch 'main' set up to track 'origin/main'

   حالا صفحه‌ی مخزن‌تان را در گیت‌هاب رفرش کنید — باید فایل‌ها را ببینید.

   ✅ اگر فایل‌ها را دیدید، این بخش تمام است.


═══════════════════════════════════════════════════════════════════════
  بخش ۵ — ساخت رمز حافظه (اجباری)
═══════════════════════════════════════════════════════════════════════

پروژه باید بین اجراها چیزهایی را به یاد بسپارد: کدام کانفیگ‌ها را قبلاً
تست کرده، کدام‌ها خراب بودند، و کدام‌ها الان در استخر ۲۰تایی هستند.

این حافظه **رمزنگاری‌شده** ذخیره می‌شود تا با اینکه مخزن عمومی است، هیچ‌کس
نتواند کانفیگ‌های شما را بخواند. برای رمزنگاری یک رمز لازم است.

─── ساخت رمز ───

۱. یک پنجره‌ی cmd باز کنید (کلید Windows → تایپ cmd → Enter)

۲. این را کپی و Enter کنید:

      powershell -c "-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 40 | %{[char]$_})"

۳. یک رشته‌ی ۴۰ حرفی چاپ می‌شود، مثلاً:

      xK9mR2pLqW7vN4tYbH8sD3fG6jZ5cX1nA0eU2iOp

   ⚠⚠ این رشته را همین الان جایی امن ذخیره کنید ⚠⚠
      (فایل متنی، یادداشت گوشی، هر جایی که گم نشود)

      اگر این رمز را گم کنید، حافظه‌ی پروژه از دست می‌رود و باید از
      صفر شروع کند. فاجعه نیست، ولی چند روز طول می‌کشد تا دوباره
      کانفیگ‌های خوب پیدا شوند.

─── ثبت رمز در گیت‌هاب ───

۴. به صفحه‌ی مخزن‌تان در گیت‌هاب بروید

۵. بالای صفحه:  Settings  (چرخ‌دنده)

۶. در ستون چپ، پایین:  Secrets and variables  →  زیرش  Actions

۷. دکمه‌ی سبز:  New repository secret

۸. پر کنید:

      Name    →   VT_STATE_PASSPHRASE
                  (دقیقاً همین، با حروف بزرگ و خط زیر)

      Secret  →   همان رشته‌ی ۴۰ حرفی که ساختید

۹.  Add secret  را بزنید.

   ✅ حالا باید VT_STATE_PASSPHRASE را در لیست ببینید.


═══════════════════════════════════════════════════════════════════════
  بخش ۶ — تنظیم لینک‌های ساب
═══════════════════════════════════════════════════════════════════════

پروژه کانفیگ‌ها را از لینک‌های ساب می‌گیرد. یک لینک پیش‌فرض گذاشته شده،
ولی می‌توانید عوضش کنید.

روش آسان — مستقیم در گیت‌هاب:

۱. در صفحه‌ی مخزن، روی فایل  subs.txt  کلیک کنید

۲. آیکن مداد (✏️) بالا سمت راست را بزنید

۳. لینک‌های خودتان را بگذارید — **هر خط یک لینک**:

      https://example.com/sub/token1
      https://example.com/sub/token2

   خطوطی که با # شروع شوند نادیده گرفته می‌شوند.

۴. پایین صفحه دکمه‌ی سبز  Commit changes  را بزنید

   ✅ تمام. دفعه‌ی بعد که پروژه اجرا شود از لینک‌های جدید می‌خواند.


═══════════════════════════════════════════════════════════════════════
  بخش ۷ — اولین اجرا
═══════════════════════════════════════════════════════════════════════

۱. در صفحه‌ی مخزن، تب  Actions  را بزنید (بالای صفحه)

۲. اگر پیام سبزی دید که می‌پرسد ورک‌فلوها را فعال کنید، تأیید کنید:

      I understand my workflows, go ahead and enable them

۳. در ستون چپ دو مورد می‌بینید:

      • بازبینی استخر     ← سریع (چند دقیقه)
      • کشف کانفیگ        ← طولانی (تا یک ساعت)

۴. اول  «کشف کانفیگ»  را بزنید — چون هنوز هیچ کانفیگی نداریم

۵. سمت راست:  Run workflow  →  دوباره  Run workflow

۶. صفحه را رفرش کنید. یک خط زرد ظاهر می‌شود (یعنی در حال اجرا).
   رویش کلیک کنید تا مراحل را زنده ببینید.

   • 🟡 زرد = در حال اجرا
   • ✅ سبز = موفق
   • ❌ قرمز = خطا (به بخش ۱۱ بروید)

۷. صبر کنید تا سبز شود. اولین بار ممکن است تا یک ساعت طول بکشد.

۸. وقتی سبز شد، در همان صفحه پایین بروید — یک خلاصه می‌بینید:

      تعداد سالم، بهترین پینگ، و جدول ۱۰ کانفیگ برتر

   ✅ از این به بعد همه چیز خودکار است. کاری لازم نیست بکنید.


═══════════════════════════════════════════════════════════════════════
  بخش ۸ — گرفتن کانفیگ‌های سالم
═══════════════════════════════════════════════════════════════════════

بعد از هر اجرا، نتایج آماده‌ی دانلود هستند.

۱. تب  Actions  →  روی آخرین اجرای سبز کلیک کنید

۲. پایین صفحه، بخش  Artifacts  →  روی فایل zip کلیک کنید (دانلود می‌شود)

۳. فایل zip را باز کنید. داخلش:

   ┌──────────────────────┬────────────────────────────────────────────┐
   │ top20_sub.txt        │ ⭐ ۲۰ تای برتر — این را در کلاینت بریزید   │
   │ top20.txt            │ همان، به صورت لینک خام                     │
   │ batches/batch_01.txt │ رتبه ۱ تا ۲۰                               │
   │ batches/batch_02.txt │ رتبه ۲۱ تا ۴۰ (و همین‌طور تا آخر)          │
   │ report.html          │ گزارش کامل — با مرورگر باز کنید            │
   │ results.json         │ داده‌ی خام (برای برنامه‌نویس‌ها)            │
   └──────────────────────┴────────────────────────────────────────────┘

─── وارد کردن در کلاینت ───

فایل  top20_sub.txt  را با Notepad باز کنید و کل متنش را کپی کنید.

  • v2rayN     →  سرور → افزودن از کلیپ‌بورد (Ctrl+V)
  • Nekoray    →  Program → Add profile from clipboard
  • v2rayNG    →  + → Import config from clipboard
  • Hiddify    →  + → از کلیپ‌بورد

نکته: خلاصه‌ی هر اجرا (بهترین پینگ و ۱۰ کانفیگ برتر) بدون دانلود هم در
صفحه‌ی همان اجرا دیده می‌شود.

نکته‌ی مهم درباره‌ی Artifact در مخزن عمومی:
  هر کاربر لاگین‌شده‌ی گیت‌هاب که آدرس مخزن شما را بداند می‌تواند
  فایل‌ها را دانلود کند. جزئیات کامل در بخش ۱۲.


═══════════════════════════════════════════════════════════════════════
  بخش ۹ — اضافه کردن تلگرام (اختیاری)
═══════════════════════════════════════════════════════════════════════

پروژه می‌تواند از کانال‌های تلگرام هم کانفیگ جمع کند. این کار کانفیگ‌های
خیلی بیشتری پیدا می‌کند.

⚠ این بخش کاملاً اختیاری است. اگر انجامش ندهید، پروژه فقط از لینک‌های
  ساب کار می‌کند و هیچ خطایی هم نمی‌دهد.

─── گام ۹.۱: گرفتن API از تلگرام ───

۱. به این آدرس بروید (فیلترشکن لازم دارید):

      https://my.telegram.org

۲. شماره‌ی تلفن تلگرام‌تان را وارد کنید

۳. تلگرام یک کد می‌فرستد (در خود اپلیکیشن، نه پیامک) — واردش کنید

۴. روی  API development tools  کلیک کنید

۵. فرم را پر کنید:

      App title  →  vtester
      Short name →  vtester
      Platform   →  Other
      بقیه       →  خالی

۶.  Create application  را بزنید

۷. دو چیز به شما می‌دهد. هر دو را یادداشت کنید:

      App api_id     →  یک عدد، مثلاً  22556457
      App api_hash   →  یک رشته‌ی ۳۲ حرفی

─── گام ۹.۲: ساخت نشست (session) ───

این مرحله روی کامپیوتر خودتان انجام می‌شود.

۱. پنجره‌ی cmd باز کنید و این را بزنید:

      pip install telethon

۲. Notepad را باز کنید و این کد را داخلش بگذارید:

      from telethon.sync import TelegramClient
      from telethon.sessions import StringSession

      API_ID = 12345678
      API_HASH = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"

      with TelegramClient(StringSession(), API_ID, API_HASH) as c:
          print()
          print("=" * 60)
          print(c.session.save())
          print("=" * 60)

   ⚠ به‌جای  12345678  عدد api_id خودتان
   ⚠ به‌جای رشته‌ی داخل گیومه، api_hash خودتان

۳. ذخیره کنید روی دسکتاپ با اسم:  make_session.py

   ⚠ در Notepad موقع ذخیره، «Save as type» را روی  All Files  بگذارید
     وگرنه اسم فایل می‌شود make_session.py.txt و کار نمی‌کند.

۴. در cmd:

      cd Desktop
      python make_session.py

۵. شماره‌ی تلفن‌تان را با کد کشور وارد کنید:  +989123456789

۶. کدی که تلگرام می‌فرستد را وارد کنید

۷. یک رشته‌ی خیلی بلند چاپ می‌شود (بین دو خط ===). کاملش را کپی کنید.

۸. ⚠⚠ **فایل make_session.py را همین الان پاک کنید** ⚠⚠
      (api_hash شما داخلش است)

─── گام ۹.۳: ثبت در گیت‌هاب ───

به  Settings → Secrets and variables → Actions  بروید و **چهار** سکرت
جدید بسازید (هر بار New repository secret):

   ┌────────────────────────┬──────────────────────────────────────────┐
   │ VT_TELEGRAM_API_ID     │ عدد api_id                               │
   │ VT_TELEGRAM_API_HASH   │ رشته‌ی ۳۲ حرفی                           │
   │ VT_TELEGRAM_SESSION    │ رشته‌ی بلند از گام ۹.۲                    │
   │ VT_TELEGRAM_CHANNELS   │ @channel1,@channel2                      │
   └────────────────────────┴──────────────────────────────────────────┘

   برای کانال‌ها: اسم کانال‌ها را با **کاما** جدا کنید، بدون فاصله‌ی اضافه.
   مثال واقعی:   @persianvpnhub,@v2ray_configs_pools

✅ تمام. از دور بعدی، تلگرام هم خوانده می‌شود.

─── هشدار امنیتی مهم ───

  رشته‌ی session یعنی دسترسی کامل به حساب تلگرام شما — بدون رمز و بدون
  کد تأیید. هرگز آن را جایی نفرستید و در فایل پروژه نگذارید.

  فقط در بخش Secrets گیت‌هاب امن است، چون گیت‌هاب آن را رمزنگاری می‌کند
  و حتی در لاگ اجراها هم نشان نمی‌دهد.

  اگر فکر می‌کنید لو رفته: تلگرام → Settings → Devices → آن نشست را
  Terminate کنید و از گام ۹.۲ دوباره بسازید.


═══════════════════════════════════════════════════════════════════════
  بخش ۱۰ — تغییر تنظیمات
═══════════════════════════════════════════════════════════════════════

همه‌ی تنظیمات در فایل  config.ci.yaml  هستند، با توضیح فارسی کنار هرکدام.

برای تغییر: در گیت‌هاب روی فایل کلیک کنید → مداد (✏️) → تغییر دهید →
Commit changes

─── پرکاربردترین‌ها ───

  تعداد کانفیگ در استخر (پیش‌فرض ۲۰):

      pool:
        size: 20          ← این را عوض کنید، مثلاً 30

      ⚠ اگر عوض کردید، دو خط پایین‌تر هم عوض کنید:
        top_file: "top20.txt"       →  "top30.txt"
        top_sub_file: "top20_sub.txt" →  "top30_sub.txt"

  تعداد کانفیگ در هر فایل دسته‌ای (پیش‌فرض ۲۰):

      pool:
        batch_size: 20

  چند کانفیگ همزمان تست شوند (پیش‌فرض ۲۴):

      test:
        concurrency: 24

      بالاتر = سریع‌تر ولی اعداد پینگ کمی نویزی‌تر

  حداکثر تست در هر دور (پیش‌فرض ۲۵۰۰):

      live:
        batch_test_size: 2500

      اگر اجراها خیلی طول می‌کشند، کمترش کنید

  بعد از چند شکست، کانفیگ کنار گذاشته شود (پیش‌فرض ۳):

      health:
        blacklist_after_failures: 3
        blacklist_hours: 24

─── تغییر زمان‌بندی ───

فایل‌های داخل پوشه‌ی  .github/workflows/  را ویرایش کنید:

  در  pool-refresh.yml  خط:

      - cron: "*/30 * * * *"     ← هر ۳۰ دقیقه

  نمونه‌های دیگر:
      "*/15 * * * *"   هر ۱۵ دقیقه
      "0 * * * *"      هر ساعت
      "0 */2 * * *"    هر ۲ ساعت

  در  discovery.yml  خط:

      - cron: "17 */6 * * *"     ← هر ۶ ساعت

  بخش ۱۱ — عیب‌یابی
═══════════════════════════════════════════════════════════════════════

─── اجرا قرمز شد ───

روی اجرای قرمز کلیک کنید، بعد روی مرحله‌ای که ❌ دارد. متن خطا را ببینید
و در جدول زیر پیدا کنید:

┌──────────────────────────────────┬──────────────────────────────────┐
│ خطا                              │ راه‌حل                            │
├──────────────────────────────────┼──────────────────────────────────┤
│ VT_STATE_PASSPHRASE تنظیم نشده   │ بخش ۵ را انجام دهید              │
│ رمزگشایی حافظه ناموفق            │ رمز را عوض کرده‌اید. شاخه‌ی data   │
│                                  │ را حذف کنید (توضیح پایین‌تر)      │
│ نشست تلگرام معتبر نیست           │ گام ۹.۲ را دوباره انجام دهید     │
│ هیچ کانفیگی پیدا نشد             │ subs.txt خالی است یا لینک‌هایش    │
│                                  │ کار نمی‌کنند                      │
│ VT_TELEGRAM_API_ID باید عدد باشد │ سکرت را اشتباه وارد کرده‌اید      │
│ محدودیت نرخ تلگرام               │ عادی است — دور بعد خودش درست     │
│                                  │ می‌شود                            │
└──────────────────────────────────┴──────────────────────────────────┘

─── حذف شاخه‌ی data (پاک کردن حافظه) ───

فقط وقتی لازم است که رمز را گم کرده یا عوض کرده باشید:

۱. در صفحه‌ی مخزن، روی دکمه‌ای که نوشته  main  کلیک کنید
۲. تب  View all branches
۳. کنار  data  آیکن سطل زباله را بزنید

دفعه‌ی بعد پروژه از صفر شروع می‌کند (چند روز طول می‌کشد تا دوباره
کانفیگ‌های خوب جمع شوند، ولی چیزی خراب نمی‌شود).

─── اجرا خودکار شروع نمی‌شود ───

گیت‌هاب زمان‌بندی مخازنی که ۶۰ روز هیچ فعالیتی نداشته‌اند را خاموش می‌کند.

راه‌حل: یک تغییر کوچک بدهید (مثلاً در README یک نقطه اضافه کنید و
Commit بزنید). زمان‌بندی دوباره فعال می‌شود.

─── اجراها با تأخیر انجام می‌شوند ───

این طبیعی است. زمان‌بندی گیت‌هاب دقیق نیست و ممکن است تا ۱۵ دقیقه دیرتر
اجرا شود، مخصوصاً در ساعات شلوغ. برای یک استخر ۲۰تایی این تفاوت مهم نیست.

─── همه‌ی کانفیگ‌ها ناموفق‌اند ───

اگر نرخ موفقیت صفر است:

  • لینک ساب‌تان را در مرورگر باز کنید — آیا واقعاً کانفیگ می‌دهد؟
  • ممکن است آن منبع دیگر کار نکند. لینک دیگری امتحان کنید.

اگر نرخ موفقیت ۲ تا ۵ درصد است: **این طبیعی است**. کانال‌های عمومی
پر از کانفیگ مرده هستند. مهم این است که ۲۰ تای برتر واقعاً کار کنند.

  بخش ۱۲ — سوالات رایج
═══════════════════════════════════════════════════════════════════════

❓ مخزن عمومی است. کانفیگ‌های من را کسی می‌بیند؟

   بگذارید دقیق و صادقانه بگویم، چون این مهم است:

   ✅ چیزهایی که واقعاً امن‌اند:

      • حافظه‌ی پروژه (شاخه‌ی data) با AES256 رمزنگاری شده. بدون رمز
        شما هیچ‌کس نمی‌تواند بازش کند — حتی اگر کل مخزن را دانلود کند.

      • رمزهای تلگرام در Secrets گیت‌هاب‌اند. گیت‌هاب آن‌ها را رمزنگاری
        می‌کند و حتی در لاگ اجراها هم نمایش نمی‌دهد.

   ⚠ چیزی که کاملاً خصوصی نیست:

      • فایل‌های خروجی (Artifact) — هر کسی که وارد حساب گیت‌هاب خودش
        شده باشد و آدرس مخزن شما را بداند، می‌تواند دانلودشان کند.
        بازدیدکننده‌ی ناشناس (بدون لاگین) نمی‌تواند.

      یعنی کانفیگ‌های سالم شما «مخفی» هستند ولی «محافظت‌شده» نیستند.
      کسی باید آدرس مخزن شما را بداند تا پیدایشان کند.

   اگر این برایتان مشکل است، دو راه دارید:

      راه ۱ — مخزن را Private کنید:
              Settings → پایین صفحه → Change repository visibility
              آن‌وقت فقط خودتان دسترسی دارید.
              هزینه: سقف ۲۰۰۰ دقیقه در ماه. باید زمان‌بندی را کم کنید
              (مثلاً بازبینی استخر هر ۲ ساعت به‌جای ۳۰ دقیقه).

      راه ۲ — رمزنگاری خروجی‌ها:
              بگویید تا ورک‌فلو را طوری تغییر دهم که فایل‌های خروجی هم
              با همان رمز شما رمزنگاری شوند. آن‌وقت مخزن عمومی می‌ماند
              (اجرای نامحدود) ولی خروجی‌ها فقط با رمز شما باز می‌شوند.
              هزینه: هر بار باید یک دستور برای رمزگشایی بزنید.

❓ واقعاً رایگان است؟

   بله. برای مخزن عمومی گیت‌هاب اجرای نامحدود می‌دهد.
   با زمان‌بندی فعلی حدود ۵۰ اجرا در روز انجام می‌شود و هزینه‌ای ندارد.

❓ باید کامپیوترم روشن باشد؟

   نه. همه چیز روی سرورهای گیت‌هاب اجرا می‌شود.
   کامپیوتر شما فقط برای دانلود نتایج لازم است.

❓ چرا فقط ۲ تا ۵ درصد کانفیگ‌ها سالم‌اند؟

   چون تست واقعی است. تسترهای معمولی که فقط پورت را چک می‌کنند ۵۰ درصد
   یا بیشتر گزارش می‌دهند، ولی آن عددها دروغ‌اند — خیلی از آن کانفیگ‌ها
   در عمل وصل نمی‌شوند.

❓ چقدر طول می‌کشد تا کانفیگ خوب پیدا شود؟

   اولین اجرا: تا یک ساعت.
   بعد از آن هر ۳۰ دقیقه استخر تازه می‌شود و هر ۶ ساعت کانفیگ جدید
   جمع می‌شود. بعد از یکی دو روز، استخر خیلی باکیفیت‌تر می‌شود چون
   کانفیگ‌های خراب کنار گذاشته شده‌اند.

❓ می‌خواهم یک لینک ساب ثابت داشته باشم که خودکار به‌روز شود

   شدنی است، ولی آن لینک برای همه قابل دیدن می‌شود. عمداً انجام نشده.
   اگر می‌خواهید، بگویید تا اضافه شود.

❓ می‌خواهم روی کامپیوتر خودم هم اجرا کنم

   پروژه‌ی اصلی در پوشه‌ی  test_config_with_xrayCore  همین کار را
   می‌کند. راهنمایش در فایل  USAGE.md  است.

❓ چطور بفهمم همه چیز درست کار می‌کند؟

   تب Actions را باز کنید. اگر آخرین اجراها سبزند، همه چیز خوب است.
   روی هر اجرا کلیک کنید تا خلاصه‌اش را ببینید.
